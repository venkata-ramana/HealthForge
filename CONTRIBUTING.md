# Contributing to HealthForge

Thank you for improving HealthForge. Start with an open issue or propose one that states the user value, scope, safety implications, and acceptance criteria. Keep pull requests focused, tested, and linked to an issue where practical.

Never include PHI, credentials, production data, or unpublished proprietary material in issues, commits, fixtures, screenshots, or logs. HealthForge provides engineering decision support; contributions must not present generated output as legal, regulatory, clinical, or compliance advice.

Run the relevant local checks, explain validation in the PR, and preserve citations and human-review controls when changing retrieval or Brief behavior. Report vulnerabilities privately using [`SECURITY.md`](SECURITY.md).
